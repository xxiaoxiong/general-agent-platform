# 智能体对话：工作目录文件面板 + 对话流顺序保真 + 产出 ZIP 下载

## 背景

用户提出三项改造（智能体对话工作台）：

1. 右侧预览区要能**切换显示当前会话工作目录下的文件**（参考 Codex 客户端：过程中产生的文件在右侧显示、点击文件名即预览内容）。
2. **对话内容按执行顺序原样展示**，去掉"最终汇总放到最后"的处理。
3. **产出文件不再逐个列出下载**，改为一个 ZIP 下载途径；单文件下载由右侧文件面板承载。

### 根因定位（已核实代码）

- 问题 2 根因：[blocks.ts](file:///d:\MyPersonalFile\MyStudyFile\AI\MyCode\AI-GeneralPlat\frontend\src\features\run\blocks.ts) 的 `setVerifiedAnswer`（L194-200）——`run.completed`/`run.failed` 携带 `summary.verification.version===2` 时，**删除全部流式过程文字块、只把最终稿 push 到消息末尾**（在工具/计划/验收卡之后），即"对话内容汇总放到最后"。
- 问题 3 根因：[VerificationCard.vue](file:///d:\MyPersonalFile\MyStudyFile\AI\MyCode\AI-GeneralPlat\frontend\src\features\run\VerificationCard.vue) 的 `verification-files` 列表逐文件渲染下载按钮。
- 问题 1 现状：右栏仅支持"单文件预览"（FilePreviewPanel），无文件列表；后端 [chat/files.py](file:///d:\MyPersonalFile\MyStudyFile\AI\MyCode\AI-GeneralPlat\backend\app\api\chat\files.py) 有 `file-preview`/`file-bytes` 但**无列目录、无 zip 端点**。

## 设计决策

| 决策点 | 结论 |
|---|---|
| 验证返工（模型重写答案）时旧草稿 | **撤回旧稿、重写稿在原位流式显示**（仿现有 `keep_chars` 撤回模式）；"截断续写"型返工（模型只补余下内容）不撤回，增量并入草稿 |
| 验收卡（verification 块）位置 | 保持在事件到达位置（执行顺序），不做重排 |
| 下载渠道 | 结尾单个「下载全部（ZIP）」按钮 + 右侧文件面板（列表、点击预览、预览内下载、面板级 ZIP）；对话正文不加链接 |
| 文件面板范围 | 会话工作区 `AGENT_FILES_ROOT/{user}/{agent}/{session}` 全部用户可见文件；排除内部目录 |

### 阶段二：前端对话流顺序（[blocks.ts](file:///d:\MyPersonalFile\MyStudyFile\AI\MyCode\AI-GeneralPlat\frontend\src\features\run\blocks.ts)）

4. **删除 `setVerifiedAnswer` 及两处调用**（`run.completed` L592、`run.failed` L607 改为 `gapFillText` 补尾，不删文本、不挪位置）。grep 确认 `msg.finalText` 无外部引用后随调用清理（类型字段可留）。

7. **gapFillText 尾部兜底**（L183-192）：现有整段前缀匹配外，增加"尾部草稿区前缀匹配"分支（v2 的 `final_text` 为交付稿，对草稿区前缀匹配时补缺尾进尾部文本块）。
8. 各场景预期块序（均按执行顺序）：
   - 无返工：`[过程文字…, 工具/计划…, 交付稿, 验收卡]`；
   - 替换返工：`[过程文字…, 工具…, 验收卡(返工中→通过), 重写稿]`（卡在其创建时刻的位置）；
   - 续写返工：`[过程文字…, 工具…, 完整交付稿, 验收卡]`；
   - 无文本/缺尾：沿用 `finalizeRunMessage` 占位与 gapFill 兜底。

## 风险与边界

- 旧事件回放缺 `continuation` 字段：按 failed_checks 兜底判续写，宁可重复不误删。
- gapFill 对截断（bounded_answer）不匹配属预期，不强行补。
- zip 大工作区内存：SpooledTemporaryFile 落盘缓冲 + 分块输出；条目上限与 file-list 一致。
- 验收卡位置随事件到达（执行顺序），返工场景卡在重写稿之前属预期，不做强制沉底。
- 不改 URL 契约既有端点；改动集中在 blocks.ts 与新增组件，遵守最小变更。
