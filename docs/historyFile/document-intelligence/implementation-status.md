# 文档智能实施与验收

## 实际交付

| 阶段 | 交付与验收证据 |
| --- | --- |
| 0 审查 | 核对了 Runtime、Worker、Skill、附件、事件、持久化与前端回放入口。见[架构记录](architecture.md)。 |
| 1 引擎与领域 | 支持规范和文档资产的不可变版本，解析 DOCX、PDF、PPTX、XLSX，生成并重读验证 DOCX。应用章节和内容块锚点 Patch，保存版本差异、事实来源和校验报告。 |
| 2 专业图与补充 | 提炼规范、生成文档和编辑文档三个路线。规范草稿经人工编辑和确认后保存。生成过程中按日期、数字、选项等字段补充资料。 |
| 3 路由与 Runtime | 显式模式和确定性自动路由共用既有 Run、Worker、租约、工具账本和 Checkpointer。增加持久化补充请求、幂等提交和同 Run 恢复。 |
| 4 对话交付 | 增加任务模式、规范草稿卡、资料补充卡和 Word 卡。历史回放、断线续读与刷新会话均能恢复对应内容。生成版本可直接预览、下载或继续编辑。 |
| 5 文档中心 | 管理私有规范和经授权发布的组织规范，展示版本、变更与任务历史，支持从文档或规范返回对话。 |
| 6 集成验收 | 后端常规套件 612 项通过。使用隔离 MySQL 补跑迁移用例 3 项通过，使用平台配置的真实模型补跑 3 项通过。前端 24 项通过，生产构建和隔离 Compose 冒烟通过。 |

核心代码集中于 `backend/app/services/documents`、`backend/app/services/agent_runtime`、`backend/app/api/v2/documents.py`、`frontend/src/features/documents` 和 `frontend/src/views/documents`。报告的实际执行链、Skill 与 Profile 的分工见[架构记录](architecture.md)，HTTP 与 SSE 契约见 [API](api.md)。

## 场景 A–I

| 场景 | 实测结果 |
| --- | --- |
| A 附件摘要 | 从真实 Word 附件读取并总结，走普通 Agent，文档资产计数不变。 |
| B 样例规范 | 提炼 DOCX 样例，修改草稿及确认发布。在另一个会话按规范名称生成。 |
| C 自然语言规范 | 无附件创建规范草稿，人工确认后保存。真实已配置模型也生成了可校验的自然语言规范草稿并进入等待确认。 |
| D 完整生成 | 从绑定 SQLite 的真实查询获取 17 项交付数据，按规范生成 Word，通过文件校验后创建版本 1。浏览器可预览和下载。 |
| E 资料补充 | 缺少完成日期时进入 `waiting_input`。错误日期返回 422，相同补充重复提交可重用，不同内容返回 409。 |
| F 局部编辑 | “把上次报告第三章的成果描述重新整理一下，其他章节不要动”创建版本 2。第 1、2、4 章结构一致，版本 1 下载字节保持一致。 |
| G 重启恢复 | 重启后端后原 Run、Checkpoint 线程、规范版本和补充请求 ID 一致。浏览器补交日期后恢复同一 Run，数据库查询成功事件和产物事件各一次。 |
| H 权限 | 跨用户访问私有规范、文档与下载返回 404。附件遍历、绝对路径和符号链接有独立边界测试。MCP 的绑定、只读和审批要求由 ToolPolicy 实行。 |
| I 普通聊天 | 自动模式走原对话图；验收中的常规问答仅发出一次模型请求。已有 SSE、审批和 Runtime 回归通过。 |

容器验收使用 MySQL、Redis、PostgreSQL Checkpointer、真实 SQLite 资料源和固定响应的 OpenAI 兼容模型服务，便于重现。最后一次完整场景的补充 Run 是 `458f2a737494469c939ab9c7f7a71e0a`，局部编辑 Run 是 `4d25ca715269404dafa9103253035e80`。Edge 验证了重启后补充、产物回放、预览、下载字节和从历史版本返回编辑。实际下载的中文 Word 经 LibreOffice 打开并渲染，检查了标题、四章正文、来源区和页码。引擎另以含表格和编号列表的样本文档验证排版。

MySQL 新建库和存量升级均到达 `e4d9074233fa`。五张新表、版本唯一键与请求序号约束通过数据库检查。专用 MySQL 的旧迁移往返测试也通过，排除了已发现的外键索引删除顺序问题。隔离环境的 `/metrics` 返回文档章节节点耗时和编辑校验计数。

## 范围与运行边界

文档编辑面向平台管理的 Word 版本，在线预览采用结构化内容，Word 分页及字体以下载文件为准。扫描件需要另行提供可提取的文字。语义质量检查使用有界的正文和来源，由已配置模型执行，文件结构校验覆盖完整 DOCX。MCP 和数据库访问遵循现有绑定与权限限制。

新镜像已在隔离 Compose 验证，正式环境按[部署与验证](operations.md)安排上线。该指南列出复跑命令、手工流程和文件清理步骤。
