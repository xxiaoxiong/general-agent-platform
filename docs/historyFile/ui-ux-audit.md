# UI/UX 现状审计

对照仓库现有路由、页面、API 封装及 Docker 运行环境完成盘点。基线截图由 Chrome 在原前端镜像和隔离后端环境中实拍，使用隔离账号和通过真实 API 建立的工作流及知识库记录。

## 工程基线

- Vue 3.5、Vite 5.4、TypeScript 5.9、Element Plus 2.14 以执行时锁文件为准。Vue Router 和 Pinia 承载鉴权、路由及用户状态，Axios 为 v1、v2 接口共用请求与反馈层。
- 旧外壳通过 Element Plus 菜单实现，当前态依赖 URL 全匹配，进入知识库详情或流程编辑器时父菜单容易丢失选中态。旧外观叠加了默认蓝色、自定义绿色与页面局部样式，表格、对话与工作流各有一套密度。
- 前端原有构建同时执行 Vue 类型检查和 Vite 打包。改造前无仓库内独立前端测试。后端可使用已有 pytest 套件验证真实协议和边界。
- Vue Flow core 1.48.2、background 1.3.2、controls 1.1.3、minimap 1.5.4 已锁定。原编辑器使用手工 SVG、坐标换算和鼠标事件。持久化结构可映射到 Vue Flow，无需更改业务数据格式。
- 数据库与后端 Docker 已存在运行服务。浏览器回归使用不同 Compose 项目和临时数据，以便验证创建、发布、删除及权限隔离。

## 页面与业务链路

| 页面 | 路径 | 原有数据和关键流程 | 改造关注点 |
| --- | --- | --- | --- |
| 登录 | `/login` | 登录、用户信息、令牌 | 表单语义、错误反馈、移动端 |
| 智能体工作空间 | `/workspace` | v2 助手、会话、Run、SSE、审批、文件和预览 | 会话导航、执行状态、输入区、产物分屏 |
| 概览 | `/dashboard` | 模型、知识、工作流、应用数量 | 真实指标、真实活动、操作入口 |
| 模型 | `/models` | 供应商、模型配置、连通性 | 双列表、密钥表单、反馈 |
| 知识库 | `/knowledge`、`/knowledge/:id` | 基础配置、文档上传、网页导入、检索 | 资源列表、详情分区、上传和索引状态 |
| 工作流 | `/workflows`、`/workflows/:id/editor`、`/workflows/:id/run` | 定义、发布标记、执行记录、节点结果、导出 | 图形适配、编辑布局、节点和运行结果 |
| 提示词 | `/prompts`、`/prompts/debugger` | 模板 CRUD、变量、历史版本及调试 | 编辑可读性、参数和输出分区 |
| 应用 | `/apps`、`/apps/instances` | 已有模板、部署及实例 API，原概览指向缺失的路由 | 恢复入口、显示真实市场数据及当前用户实例 |
| 数据库 | `/databases`、`/databases/:id/query` | 连接、测试、结构读取、只读 SQL。自然语言工具原为上下文拼装 | 状态表、结构导航、可复制查询上下文 |
| 评测与运行 | `/system/evaluation` | 数据集、用例、评测任务、客观指标、事件和工具轨迹、版本对比、客观简报、建议和回滚 | 数据密度、加载及详情、真实事件层级 |
| 用户与审计 | `/system/users`、`/system/audit` | 账户管理、状态、分页、日志查询和详情 | 统一筛选与空状态、危险操作确认 |
| 扩展管理 | `/system/skills`、`/system/mcp` | 技能文件、注入范围、MCP 服务和工具策略 | 保留高级表单，以清晰列表呈现服务与状态 |

评测、用户、审计、技能和 MCP 路由使用原有管理员守卫。应用模板读取和实例列表依赖原登录权限，实例列表由 API 按所有者返回。Langfuse 由现有 Run 或评估响应提供带项目 ID 的地址。独立 Trace 模块和独立模型供应商管理路由均未在原路由表定义。
