# UI/UX 实施与验收计划

## 实施顺序

1. 在原前端镜像和隔离业务服务上记录页面基线。核实路由、权限、API、工作流定义和前端依赖。
2. 建立浅色与暗色 Token、Tailwind 工具类和 Element Plus 兼容层。接入 Reka UI 导航浮层、对话框和菜单。统一页面标题、操作区、表格外框、空状态和错误反馈。
3. 优先整理智能体对话。会话面板、消息和输入区共享现有 SSE 与审批协议，右侧面板复用已有文件预览。跟随最新消息的行为由用户滚动位置决定。
4. 推进模型、知识库、提示词、应用与概览。表格呈现高密度数据，表单和详情使用现有接口。按后端权限恢复应用市场与实例路由。
5. 通过 Vue Flow 适配工作流画布。把拖拽、连线、选区与缩放视为前端呈现。保存以历史业务定义为源，节点配置、未知字段、边顺序和旧端点键参与回归。
6. 统一评测、用户、审计和扩展管理页面。保留客观简报的数据来源及现有 Langfuse 地址，按真实 Run 事件和工具记录呈现执行明细。
7. 执行回归和镜像冒烟。浏览器检查 1920、1440、1366、1024 与手机宽度，使用真实 API 验证关键事务，记录外部集成依赖和验收边界。

## 技术选择

- Tailwind 4 使用 Vite 插件，配置文件采用 ESM。Vue 3.5 支持 Reka UI 2，基础组件源码以 shadcn-vue 的本地维护模式组织。禁用 Tailwind Preflight，沿用 Element Plus 对旧表单和复杂控件的原生支持。
- 正式导航和新组件采用维护中的 Lucide Vue 包。日期选择器、上传、复杂表格、表单校验和既有反馈服务继续使用 Element Plus，由统一兼容层提供主题。
- Vue Flow 迁移集中在画布边界。定义携带的业务字段和旧边结构继续按源记录存储。服务端执行接口返回最终节点结果，编辑器据此显示真实结果，等待期间显示运行状态。
- 应用市场和实例加回路由并沿用现有 API 的登录范围。未注册的独立管理模块以原有评测页、对话详情或外链为入口。

## 验收方法

| 领域 | 检查项 |
| --- | --- |
| 外壳与权限 | 登录成功与失败、常规账号与管理员菜单、管理员深链接、窄屏抽屉、键盘命令、明暗持久化 |
| 智能体 | 新建、过滤、切换、删除、输入法、消息流、工具和审批、附件上传下载与预览、滚动 |
| 资源 | 模型配置与连通性、知识文档入库与检索、模板编辑及调试、应用列表与实例 |
| 工作流 | 创建、拖放、连线、保存重载、发布、运行、调试与节点结果 |
| 运行和管理 | 数据集、评测与 Run 工具时间线、客观简报、用户管理、日志过滤和详情 |
| 工程 | Vue 类型检查、测试、正式构建、Docker 镜像更新、真实页面截图与异常记录 |
